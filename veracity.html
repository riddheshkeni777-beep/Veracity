Overview

Veracity is an institutional-grade misinformation detection platform that combines large language model reasoning with a live network of 4,500+ trusted sources. It is designed for analysts, journalists, researchers, and institutions who need fast, explainable, and auditable verdicts on digital claims.

fact_check

AI-Powered Analysis

Every claim is processed by the V-4 Forensic Engine — a multi-pass reasoning pipeline with built-in source triangulation.

image_search

Multimodal Input

Attach images alongside text. The engine performs OCR, reverse-image fingerprinting, and visual context extraction.

lock

Session-Scoped Privacy

All case data is scoped to your browser session. No claim text is stored on Veracity servers beyond the duration of processing.

lightbulb

Quick start: Paste a headline, article excerpt, or social media post into the Analysis Hub on the Dashboard, optionally attach an image, select a priority level, then click Verify Now. Results are typically ready in 8–25 seconds.

edit_note

Submitting a Claim

1 — Source Material

Paste any text into the Source Material field: a news headline, full article paragraph, tweet, WhatsApp forward, or any claim you want verified. There is no hard character limit, but inputs over 2,000 characters are automatically truncated to the most semantically dense portion for processing.

✓ "Scientists confirm 5G towers cause cancer in new peer-reviewed study"
✓ Full article excerpt (up to ~2,000 chars)
✗ Empty input — you must provide text or an image

2 — Image Evidence (Optional)

Click the drop zone or drag an image to attach visual evidence. Supported formats: JPG, PNG, WEBP. Maximum file size: 10 MB. When an image is attached, the engine runs a parallel visual analysis pass and merges the findings with the text verdict before producing the final score.

3 — Priority Level

Level Passes Typical Time Best For
Standard Analysis 1 reasoning pass + source check 8–12 s Quick sanity checks, daily use
Expedited Verification 2 passes + entity resolution 12–20 s Breaking news, trending claims
Institutional Deep-Dive 3 passes + adversarial probing 20–35 s High-stakes, publication-grade
speed

Verdicts & Scoring

Each submission receives a Veracity Score (0–100) and a categorical verdict. The score reflects the engine's confidence in the claim's truthfulness — higher = more credible.

TRUE

Score ≥ 75

Claim is supported by multiple independent, high-authority sources. Minor inaccuracies may exist but do not materially alter the core assertion.

MISLEADING

Score 40–74

Contains factual elements but is framed, cherry-picked, or presented in a way that creates a false impression. Requires context to be accurate.

FAKE

Score < 40

Directly contradicted by authoritative evidence, fabricated, or a known piece of viral misinformation. The claim should not be shared.

V-4 Forensic Engine

The V-4 engine is Veracity's fourth-generation analysis pipeline. It processes each claim through a series of sequential, auditable passes before producing a final verdict.

Analysis Pipeline

1

Ingestion & Normalisation

Text is stripped of HTML, normalised for encoding, and split into individual claims for independent evaluation.

arrow_downward
2

Semantic Decomposition

Named entities, dates, statistics, and causal claims are extracted and tagged for targeted fact-checking.

arrow_downward
3

Source Triangulation

Claims are cross-referenced against the live source network (4,500+ nodes) and, if configured, the Google Fact Check Tools API. Wikipedia is used as a secondary fallback.

arrow_downward
4

LLM Reasoning Pass

A large language model synthesises source evidence, linguistic signals, and structured claim data into a coherent verdict with a natural-language explanation.

arrow_downward
5

Score Calibration & Output

Raw confidence values are calibrated against a rolling reference corpus, the final Veracity Score is computed, and the result is returned with full audit metadata.

Image Analysis

When an image is attached, a parallel visual pipeline runs concurrently with the text pipeline:

document_scanner

OCR Extraction

Text embedded in the image is extracted and merged with the primary text input before semantic analysis.

image_search

Reverse Fingerprinting

Perceptual hashing detects whether the image matches known manipulated or out-of-context media in the forensic database.

auto_fix_high

Manipulation Detection

Error Level Analysis (ELA) and metadata inspection flag potential splices, edits, or AI-generated visuals.

context_menu

Context Coherence

Visual content is checked for alignment with the text claim — e.g., detecting stock photos presented as original event photography.

API Integration

key

Google Fact Check Tools API: Veracity optionally integrates with the Google Fact Check Tools API to augment source triangulation. Configure your key under Settings → Google Fact Check API Key. Without a key, the engine falls back to the Wikipedia tier.

Obtaining a Google Fact Check API Key

  1. Go to console.cloud.google.com and create or select a project.
  2. Navigate to APIs & Services → Library and search for Fact Check Tools API.
  3. Click Enable, then go to Credentials → Create Credentials → API Key.
  4. Copy the key and paste it into Settings → Google Fact Check API Key inside Veracity.

Privacy & Data Handling

Veracity is designed with a session-first data model. All case data — including claim text, images, and verdicts — is stored exclusively in your browser's session storage and is erased when you close the tab.

check_circle

Claim text is not persisted on Veracity servers after processing completes.

check_circle

Images are transmitted over TLS and deleted from processing nodes within 60 seconds of analysis.

check_circle

Profile data (name, bio, avatar color) is stored only in your browser's localStorage and never sent to Veracity servers.

check_circle

Aggregated, non-identifiable analytics (verdict distribution, average score) may be used to improve model calibration.

For full details, refer to the Veracity Privacy Policy at veracity.io/privacy.

Frequently Asked Questions

Can Veracity analyse content in languages other than English? expand_more

The V-4 engine has baseline support for 14 languages including Spanish, French, Hindi, Portuguese, Arabic, and German. However, source triangulation coverage is strongest for English-language claims, and scores for non-English input may carry wider uncertainty margins.

How should I interpret a score in the 40–55 range? expand_more

A score of 40–55 sits in the "borderline misleading" zone. This typically means the claim contains a factual kernel but is framed in a way that could mislead without additional context. The AI explanation panel will highlight specific phrases or figures that drove the score down. Treat these cases as requiring manual editorial review before publication.

Does the platform store my submitted claims for training purposes? expand_more

No. Individual claim text is not retained for model training. Only anonymised, aggregated statistical signals (e.g., verdict distribution, token-level linguistic patterns stripped of content) may feed into periodic model calibration updates.

Why did my claim receive a MISLEADING verdict even though I believe it is true? expand_more

The engine evaluates claims as submitted, including their framing. A technically accurate statistic presented without necessary context (e.g., a percentage without base rate, or a quote taken out of temporal context) will score lower than the same data presented completely. Resubmit with fuller context and the score will typically improve.

What is the difference between Free Tier and Institutional Plan? expand_more

Free Tier provides unlimited single-claim submissions via the web interface, with Standard and Expedited priority levels, session-scoped history, and Wikipedia-tier source fallback. Institutional Plan adds Institutional Deep-Dive priority, REST API access with webhook callbacks, team workspaces, audit-log exports, Google Fact Check API integration managed by Veracity, and dedicated support.
